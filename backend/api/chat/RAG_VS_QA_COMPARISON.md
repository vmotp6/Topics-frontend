# RAG AI 系統 vs QA AI 系統 完整對比

## 📋 系統概述

### QA AI 系統（舊系統）
- **位置**：`backend/api/ollama/ollama_api.php`
- **資料庫**：`ollama` 資料庫的 `ollama_training_data` 表
- **工作方式**：關鍵詞匹配 → 資料庫查詢 → AI 回答（最後手段）

### RAG AI 系統（新系統）
- **位置**：`backend/api/chat/rag_chat_api.php`
- **資料庫**：`ollama` 資料庫的 `rag_knowledge_base` 表
- **工作方式**：智能搜索 → 構建上下文 → AI 生成回答（核心功能）

---

## 🔍 核心差異對比

### 1. 搜索策略

#### QA AI 系統
```
用戶問題 → 字符串匹配 → 相似度計算 → 返回預設答案
```
- ❌ 只能找到完全匹配或高度相似的資料
- ❌ 搜索範圍有限
- ❌ 無法理解問題的語義

#### RAG AI 系統
```
用戶問題 → 全文搜索 + LIKE + 關鍵詞匹配 → 相似度計算 → 構建上下文 → AI 理解並生成
```
- ✅ 多種搜索策略，找到更多相關資料
- ✅ 理解問題的語義
- ✅ 可以整合多個資料來源

---

### 2. 回答生成方式

#### QA AI 系統
```php
// 如果找到匹配 → 直接返回資料庫答案
if (找到完全匹配) {
    return 資料庫答案;  // 生硬的回答
} else {
    return AI回答;      // 但沒有上下文
}
```

**問題**：
- 回答較生硬，像機器人
- 無法整合多個資料來源
- 如果資料庫沒有，AI 回答缺乏上下文

#### RAG AI 系統
```php
// 搜索相關資料 → 構建上下文 → AI 生成
if (找到相似資料) {
    上下文 = 整合多個相關資料;
    return AI生成(問題 + 上下文);  // 自然流暢的回答
} else {
    return AI生成(問題);           // 但 AI 能力更強
}
```

**優勢**：
- ✅ AI 理解上下文，生成自然回答
- ✅ 可以整合多個資料來源
- ✅ 即使沒有資料，AI 也能提供有用回答

---

### 3. 資料管理方式

#### QA AI 系統
```
需要為每個問題準備對應的答案：
{
  "question": "護理科的課程有哪些？",
  "answer": "護理科的課程包括..."
}
```

**限制**：
- ❌ 需要手動配對問題和答案
- ❌ 無法處理問題的變體
- ❌ 維護成本高

#### RAG AI 系統
```
只需添加知識內容：
{
  "title": "護理科課程介紹",
  "content": "護理科的課程包括基礎醫學、護理理論...",
  "keywords": "護理,課程,科系"
}
```

**優勢**：
- ✅ 只需添加知識，不需要配對
- ✅ AI 自動理解和使用
- ✅ 可以處理問題的各種變體
- ✅ 維護成本低

## 🎯 RAG 系統的核心優勢

### 1. **智能上下文理解**
- RAG：AI 理解搜索到的資料，整合生成回答
- QA：直接返回資料，無法整合

### 2. **更強的搜索能力**
- RAG：全文搜索 + 多種策略，找到更多相關資料
- QA：簡單匹配，可能遺漏

### 3. **更自然的回答**
- RAG：AI 生成，像真人對話
- QA：資料庫答案，較機械化

### 4. **更好的擴展性**
- RAG：只需添加知識內容
- QA：需要配對問題和答案

### 5. **處理未見過的問題**
- RAG：AI 根據上下文推理回答
- QA：只能回答預設問題

### 6. **整合多個資料來源**
- RAG：可以整合多個相關資料生成完整回答
- QA：只返回單一答案
